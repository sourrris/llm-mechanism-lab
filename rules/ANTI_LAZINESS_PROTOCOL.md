# Anti-laziness protocol

## Central mechanism

Avoidance grows when the task is vague, the first action is large, feedback is delayed and escape routes are abundant. The repo removes those conditions.

## Rules

### 1. No zero, no fake completion

On a bad day, execute the published floor. It keeps contact with difficulty. It does not mark the full gate complete.

### 2. Never restart

Restarting feels clean because it avoids confronting the exact point of failure. Resume from the earliest failed test, prediction or explanation.

### 3. Hard thing before novelty

No new tool, repo, model, video, paper or dashboard change until today’s first failing test has been produced.

### 4. Two attempts before rescue

Attempt once from first principles. Inspect the failure. Attempt again with a revised hypothesis. Only then ask AI for one hint.

### 5. Reduce scope, not rigor

When overloaded, cut optional reading, model size, dataset size or polish. Do not cut prediction, measurement, causal distinction or evidence.

### 6. Commit discomfort

Keep failed predictions and bug autopsies. Deleting them protects ego and destroys the learning signal.

### 7. Reward follows evidence

Entertainment begins after a tangible artifact exists: a passing test, a completed derivation, a plot, a causal intervention or a recorded defense.

## Five-minute entry actions

Choose one when resistance is high:

- Write one prediction that can be wrong.
- Calculate one attention score row by hand.
- Run one failing test and name the earliest wrong assumption.
- Explain one tensor shape aloud.
- Open only today’s TODO and write the function signature from memory.

The aim is not to feel ready. The aim is to cross from avoidance into contact with the mechanism.
